# 本地推理真实成本（实测）
- 样本：llama-qwen27b.log ｜ 1 段会话 ｜ 请求 5 个
- 开机 308.7s（5.1 分钟，冷启动 85.9s）｜ 实际计算 61.0s ｜ **占空比 19.8%**
- 产出：入 7383 tok / 出 2119 tok（入:出 = 3.48:1）｜ 出速 **34.7 tok/s**
- 电费口径：0.1200 ¥/小时（开机即计费，不论是否在算）

| 口径 | 单价 | 说明 |
|---|---|---|
| A 满负荷边际 | **¥0.96/M 出** | 全速跑才成立，跑分口径 |
| B 本次账单 | **¥4.86/M 出** | 0.010290 元 ÷ 2119 tok |
| C 云端同工作量 | **¥7.97/M 出**（¥0.016890 元）| deepseek-v4-flash：入 1.065 + 出 4.26 |
| D 保本占空比 | **12.0%** | A=C 的临界点；实测 19.8% → **本地赢** |

- 同工作量比价：本地 ¥0.010290 vs 云端 ¥0.016890 → **本地便宜**（39%）
- 判据：占空比 = 计算秒数 ÷ 开机秒数。它由「一天几个 job、每个 job 多长」决定，跟 tok/s 跑分无关。
- 冷启动：85.9s（0.002863 元/次；按小时租的机器上这 86s 也是计费的）
- 投影公式：开机 H 小时的账单 = H × ¥0.12（跟有没有在算无关）。打平云端需要**平均**出速 ≥ 4.2 tok/s（= 保本占空比 12% × 实测出速 34.7 tok/s；同 3.5:1 输入比口径），而纯解码峰值是 38.7 tok/s。

# 本地推理真实成本（投影 5.5h 开机）
- 样本：llama-qwen27b.log ｜ 1 段会话 ｜ 请求 5 个
- 开机 19800.0s（330.0 分钟，冷启动 85.9s）｜ 实际计算 61.0s ｜ **占空比 0.3%**
- 产出：入 7383 tok / 出 2119 tok（入:出 = 3.48:1）｜ 出速 **34.7 tok/s**
- 电费口径：0.1200 ¥/小时（开机即计费，不论是否在算）

| 口径 | 单价 | 说明 |
|---|---|---|
| A 满负荷边际 | **¥0.96/M 出** | 全速跑才成立，跑分口径 |
| B 本次账单 | **¥311.47/M 出** | 0.660000 元 ÷ 2119 tok |
| C 云端同工作量 | **¥7.97/M 出**（¥0.016890 元）| deepseek-v4-flash：入 1.065 + 出 4.26 |
| D 保本占空比 | **12.0%** | A=C 的临界点；实测 0.3% → **本地亏** |

- 同工作量比价：本地 ¥0.660000 vs 云端 ¥0.016890 → **本地更贵**（3808%）
- 判据：占空比 = 计算秒数 ÷ 开机秒数。它由「一天几个 job、每个 job 多长」决定，跟 tok/s 跑分无关。
- 冷启动：85.9s（0.002863 元/次；按小时租的机器上这 86s 也是计费的）
- 投影公式：开机 H 小时的账单 = H × ¥0.12（跟有没有在算无关）。打平云端需要**平均**出速 ≥ 4.2 tok/s（= 保本占空比 12% × 实测出速 34.7 tok/s；同 3.5:1 输入比口径），而纯解码峰值是 38.7 tok/s。

> 同一批 token、同一台机器，只是把开机时间从 5.1 分钟拉到夜间窗口 5.5h。
> 占空比 0.3% < 保本线 12.0% → 单价从 ¥4.86/M 涨到 ¥311.47/M。
> 这就是 NIGHT.md N4「无活不开机」的量化依据：钱花在**开机**上，不是花在 token 上。
